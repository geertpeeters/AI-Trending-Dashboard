Help · operating the dashboardHelp · het dashboard bedienen

Operational manual: how the site gets its data, what runs when, and how to change things safely.Operationele handleiding: waar de site zijn data vandaan haalt, wat wanneer draait en hoe je veilig dingen wijzigt.

1 · Daily rhythmDagelijks ritme

The site is a static build. Every day at 06:00 UTC the scheduler container runs a crawl: fetch sources, score items, AI-review, then re-render every page. The timestamp in the header shows when the current build finished.De site is een statische build. Elke dag om 06:00 UTC draait de scheduler-container een crawl: bronnen ophalen, items scoren, AI-review en daarna alle pagina's opnieuw renderen. De tijd in de header is het moment waarop de huidige build klaar kwam.

Between runs you can trigger a crawl yourself: Manage → crawl now (writes only from your home network). Changes you make on the Manage page are applied at the next crawl.Tussen runs door kun je zelf een crawl starten: Beheren → nu crawlen (schrijven alleen vanaf je thuisnetwerk). Wijzigingen op de Beheerpagina gelden bij de volgende crawl.

3 · Settings (.env)Instellingen (.env)

  • OMNIROUTE_URL / OMNIROUTE_API_KEY — OpenAI-compatible gateway the AI-review runs on (URL from inside the gateway network).OpenAI-compatibele gateway waarop de AI-review draait (URL vanuit het gateway-netwerk).
  • OMNIROUTE_MODEL — model preference; auto/best-fast is the fastest for 8-item review batches.modelvoorkeur; auto/best-fast is het snelste voor 8-items review-batches.
  • WRITE_NETWORKS — networks allowed to write via the website (references, topics, sources, crawl). Empty = deny all. The 403 message shows your IP and the allowed ranges; 172.16.0.0/12 covers docker, so opening the site from the server itself also works.netwerken die mogen schrijven via de website (referenties, topics, bronnen, crawl). Leeg = alles geweigerd. De 403-melding toont jouw IP en de toegestane ranges; 172.16.0.0/12 dekt docker, dus de site openen vanaf de server zelf werkt ook.
  • RATING_SALT — salt for anonymising rating IPs (change it in production)zout om rating-IP's te anonimiseren (wijzig dit in productie)
  • MAX_WRITES_PER_HOUR / MAX_RATINGS_PER_HOUR — rate limits per IPrate-limits per IP
  • GITHUB_TOKEN — optional: higher GitHub search rateoptioneel: hoger GitHub-zoekratio
  • PORT — server port inside the container (default 8184)serverpoort in de container (standaard 8184)

After changing .env or server code: docker compose up -d --build (containers are recreated, so the new settings apply).Na wijzigen van .env of servercode: docker compose up -d --build (containers worden opnieuw aangemaakt, de nieuwe instellingen gelden dan).

  • References: a curated URL per category; injected into the index at the next crawl and never dropped.Referenties: een handmatige URL per categorie; wordt bij de volgende crawl in de index gezet en nooit gedropt.
  • Topics: search queries that drive source fetches and AI keyword matching. AI-generated topics are marked with · AI.Topics: zoekopdrachten die het ophalen van bronnen en de AI-sleutelwoordmatch sturen. AI-gegenereerde topics zijn gemarkeerd met · AI.
  • Sources: extra feeds/searches per category (hn_search, github_search, arxiv, rss, openrouter).Bronnen: extra feeds/zoekopdrachten per categorie (hn_search, github_search, arxiv, rss, openrouter).
  • Crawl now: starts a full crawl in the background; refresh the page in a few minutes.Nu crawlen: start een volledige crawl op de achtergrond; ververs de pagina over enkele minuten.
  • Every change is logged in the changelog on this page and applied at the next crawl. Writes are limited to WRITE_NETWORKS and to a maximum of 60 per hour per IP.Elke wijziging staat in het changelog op deze pagina en geldt bij de volgende crawl. 5 · How the AI review worksZo werkt de AI-review

Each batch of up to 8 items is scored (relevance 0-10, keep/drop), tagged, and given a summary (600-800 chars), a one-line purpose and a kind (tool/model/paper/…). Results land in data/items.json: summary, purpose, kind, relevance, tags, ai_verdict and ai_reviewed_at.Elke batch van maximaal 8 items wordt gescoord (relevantie 0-10, keep/drop), getagd en krijgt een samenvatting (600-800 tekens), een éénregelige purpose en een soort (tool/model/paper/…). De resultaten staan in data/items.json: summary, purpose, kind, relevance, tags, ai_verdict en ai_reviewed_at.

Self-healing: an item without a purpose is picked up again by the next run, even inside the 7-day review window. So if a batch failed (gateway timeout), the next crawl simply retries it — nothing is lost.Zelfherstel: een item zonder purpose wordt door de volgende run weer opgepakt, zelfs binnen het 7-dagen review-venster. Als een batch dus faalde (gateway-timeout), probeert de volgende crawl het gewoon opnieuw — er gaat niets verloren.

Failing batches are logged and retried with backoff. For a full backfill after a prompt change, run: python3 pipeline/crawl.py --resummarize.Gefaalde batches worden gelogd en met backoff opnieuw geprobeerd. Voor een volledige backfill na een promptwijziging: python3 pipeline/crawl.py --resummarize.

7 · TroubleshootingProblemen oplossen

  • 403 on saving — your IP is not in WRITE_NETWORKS; the error message shows the IP the server saw and the allowed ranges.jouw IP staat niet in WRITE_NETWORKS; de foutmelding toont het IP dat de server zag en de toegestane ranges.
  • HTML instead of JSON — a proxy or server error page reached the browser; the UI now reports this as "server did not respond with JSON (HTTP …)". Check docker logs ai-trending-web.een proxy- of serverfoutpagina bereikte de browser; de UI meldt dit nu als "server antwoordde niet met JSON (HTTP …)". Kijk in docker logs ai-trending-web.
  • Crawl will not start — data/.crawl.lock exists and is fresh: another crawl is running. It is stale after 30 minutes or when the holding pid is dead.data/.crawl.lock bestaat en is recent: er draait al een crawl. Hij is verouderd na 30 minuten of als de pid dood is.
  • AI review slow or failing — gateway peaks last 20-60 minutes; batches time out and are retried next run. Check data/logs/ and the gateway itself.gateway-pieken duren 20-60 minuten; batches lopen vast en worden de volgende run opnieuw geprobeerd. Kijk in data/logs/ en naar de gateway zelf.
  • Site not updated — look in data/logs/web-trigger-*.log or docker logs ai-trending-scheduler; /healthz must return {"status":"ok"}.kijk in data/logs/web-trigger-*.log of docker logs ai-trending-scheduler; /healthz moet {"status":"ok"} teruggeven.
  • Item vanished — items are pruned 30 days after their last sighting by any source; manual references are re-injected every crawl.items verdwijnen 30 dagen na hun laatste waarneming door een bron; handmatige referenties worden elke crawl opnieuw geïnjecteerd.

8 · Privacy and securityPrivacy en beveiliging

  • Ratings are stored as a hash of your IP + RATING_SALT, never as a raw address.Beoordelingen worden bewaard als hash van je IP + RATING_SALT, nooit als ruw adres.
  • All writes (references, topics, sources, crawl) are restricted to WRITE_NETWORKS and rate-limited per IP.Alle schrijfacties (referenties, topics, bronnen, crawl) zijn beperkt tot WRITE_NETWORKS en rate-limited per IP.
  • The site is fully static; there are no third-party trackers or analytics.De site is volledig statisch; geen third-party trackers of analytics.
